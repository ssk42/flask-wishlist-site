# EARS Specifications: Price Processing

- [x] **AUTO-PRC-001**: While processing async price batches, if the system encounters an Amazon URL, it shall process the Amazon requests sequentially (one at a time) to prevent memory exhaustion, while processing non-Amazon URLs concurrently (up to 5 at a time).
- [x] **AUTO-PRC-002**: When the system fetches a new price, it shall record the new price in `PriceHistory` if the price changed by more than $0.01, or if it has been more than 6 hours since the last record.
- [x] **AUTO-PRC-003**: When a price drops by 10% or more compared to its old price, the system shall generate a Notification for the item owner.
- [x] **AUTO-PRC-004**: When a price drops by 10% or more, if the item is `Claimed` or `Purchased` by a user other than the owner, the system shall generate an additional Notification for the claimer.
- [x] **AUTO-PRC-005**: If the `AMAZON_STEALTH_ENABLED` flag is true, the system shall attempt to fetch Amazon prices using the identity manager and headless browser stealth mode before falling back to legacy extraction.
- [x] **AUTO-PRC-006**: When `update_stale_prices` executes, it shall identify items whose `price_updated_at` is older than 7 days, or is null, and attempt to fetch updated prices for them.
- [x] **AUTO-PRC-007**: If an item's URL price fetch fails during a batch update, the system shall stamp the item's `price_updated_at` to approximately 6 days old (retry pacing) so the item crosses the 7-day staleness window again in about a day — failed URLs retry ~daily instead of being treated as freshly updated (full 7-day wait) or hammered on subsequent immediate runs.
- [x] **AUTO-PRC-009**: When `update_stale_prices` processes a batch of URLs, it shall process them in chunks of 25 and commit each chunk to the database as it completes, so completed chunks survive a task time-limit kill instead of being lost to a single final commit.
- [x] **AUTO-PRC-010**: **If** a non-Amazon URL fetch during a batch update fails with an HTTP 403 or 429 status (a bot block) **or** returns HTTP 200 with no parseable price (a JS-rendered price, e.g. Target) and `BROWSER_RESCUE_ENABLED` is true, the system shall retry that URL through the headless browser, sequentially, and record the attempt with `method='browser_rescue'`; a network error shall not trigger a rescue. Responses with no price shall not be cached, so they are retried rather than shelved.
- [x] **AUTO-PRC-008**: When fetching metadata via the generic fallback, the system shall prioritize extracting data from `og:*` metadata tags (e.g., `og:price:amount`, `og:image`) before falling back to HTML parsing.
- [ ] **AUTO-PRC-011**: If an automatic price fetch for an item fails during a batch update, the system shall increment the item's `price_fail_streak`; when the new streak is greater than or equal to the backoff floor (`PRICE_BACKOFF_FLOOR`, default 3), it shall also set `price_backoff_until` to now plus min(2 × 2^(streak − floor) days, `PRICE_BACKOFF_MAX_DAYS` in days); below the floor it shall leave `price_backoff_until` unset so ~daily retry pacing is preserved.
- [ ] **AUTO-PRC-012**: When any price fetch for an item succeeds — via the batch update path or `refresh_item_price` — the system shall reset `price_fail_streak` to 0 and clear `price_backoff_until`.
- [ ] **AUTO-PRC-013**: When selecting items needing a price update, the system shall exclude items whose `price_backoff_until` is in the future and automatically include them again once that time has passed.
- [ ] **AUTO-PRC-014**: When an item's `link` value changes through any write path, the system shall reset `price_fail_streak` to 0 and clear `price_backoff_until`, detected via a single SQLAlchemy `before_flush` listener registered with other model events, without per-blueprint edits.
- [ ] **AUTO-PRC-015**: When a manual refresh runs for a backed-off item, the system shall ignore `price_backoff_until`, attempt the price fetch anyway, and on success reset both backoff fields.
- [ ] **AUTO-PRC-016**: The system shall read the backoff floor from `PRICE_BACKOFF_FLOOR` (default 3) and the maximum backoff delay from `PRICE_BACKOFF_MAX_DAYS` in days (default 30).
- [D] **AUTO-PRC-017**: [DEFERRED] When an item is currently backed off, the UI shall show a user-visible indication (e.g. card badge) that automatic pricing is paused; not scheduled for this segment.
