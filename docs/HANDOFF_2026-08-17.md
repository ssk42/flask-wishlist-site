## The CI gate work (PR #63) — MERGED, all gates live on main

PR #63 rewrote `.github/workflows/tests.yml` to fix the exit-code swallow
(the old code treated any non-zero pytest exit with `failures=0` as "teardown
noise" — silently bypassing the 90% coverage gate, collection errors, usage
errors) and added new gates. **The gate proved itself** — the PR run caught
three real bugs, all fixed on the branch before merge:

1. **Migration downgrade broken** (FIXED, committed to the branch):
   `4a8b3c9d1e2f` (guard migration) had a downgrade that batch-dropped indexes
   created by the previous migration — failed on Postgres. Now a pure no-op;
   `3bf7272ee759` owns teardown and drops the table directly (batch-op `f()`
   index drops removed — redundant and broken on PG). Migration job now passes.
2. **safety CLI broken** (FIXED in workflow): safety 3.2.14 crashes at import
   against ALL current typer versions (`typer.rich_utils` AttributeError).
   Replaced with `pip-audit -r requirements.txt` in the workflow.
3. **Siri AppIntents code needs the iOS 27 SDK** (RESOLVED on the branch):
   `@available(iOS 27, *)` + `.system.open`/`.system.searchInApp` schema
   members only exist in Xcode 27's SDK. macos-15's Xcode 16.4 can't parse
   `@AppIntent`; macos-26's Xcode 26.6 parses it but lacks the schema members.
   Resolution: the app-build CI step is gated on `xcodebuild` major >= 27 and
   auto-activates when hosted images ship Xcode 27; WishlistKit tests always
   run (they pass on 26.6). Deliberately did NOT `#if` the intents out — that
   would break them for all real builds, not just CI.
